# 统一 LLM 客户端开发规范

本目录是 Dazah 后端普通业务调用 LLM 的唯一平台入口。业务模块必须通过
`from app.core.llm import llm_client` 调用模型，不得直接实例化旧 AI 客户端、
手工读取模型配置环境变量或创建旁路 provider。本目录自身负责供应商适配与
配置管理；Hermes 编排层的运行配置按其规范维护，业务模块不得借用 Agent 通道。

## 调用边界

- 文本、JSON、视觉和流式调用使用现有客户端公开方法，签名以 `client.py`
  为准。自然语言或 Markdown 显式使用 `chat(..., response_format=None)`；
  `chat_json`/`chat_vision_json` 的 `expected_keys` 只检查必要字段是否存在，
  调用方仍须校验类型、枚举、长度与数值范围，不直接写入关键业务字段。
- 模型选择、数据库配置优先级、开发环境回退和连接生命周期由本目录统一管理。
- 业务模块只传业务输入和必要调用参数，不处理密钥解密、provider 认证或底层连接关闭。
- 结构化输出必须校验格式和必要字段；不能把无法解析的模型输出直接作为稳定 API 响应。
- 不在 prompt、日志、异常、审计或响应中泄露 secret、token、password、key 或不必要的个人数据。

## 错误与可靠性

- 使用本目录统一异常类型区分无配置、输出格式错误、供应商错误和限流。
  `LLMRateLimitError` 继承 `LLMProviderError`，分别捕获时先处理限流；超时
  当前通过 `LLMProviderError` 表达，按其状态和安全业务语义映射，不臆造异常类。
- 超时、重试和限流策略应有明确上限；有副作用的业务流程不得因模型调用自动重复执行写操作。
- 模型输出不能替代审批、驳回、批准等人工责任判断。
- 新增 provider 或公共方法时保持现有调用方兼容，并补充成功、无配置、无效输出、超时、限流和供应商失败测试。

新增或修改 LLM 环境变量时，同步工作区根目录 `.env.example` 和 `.env.local.example` 的变量名，但不得读取、生成或写入真实密钥。

普通业务规则变更只 mock 业务模块实际导入的 `llm_client`，不连接真实模型。
客户端或 provider 变更则在本目录的实际调用边界 mock 传输与配置；配置探测和
连通性接口的存在不构成开发测试可使用真实密钥或真实供应商的授权。
