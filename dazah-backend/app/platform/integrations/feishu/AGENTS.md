# 飞书平台集成开发规范

本目录只承载跨业务模块可复用的飞书基础能力，例如 HTTP/API 客户端、鉴权协议、事件接入、消息发送、URL 与标识解析和调用方显式传参的连通性测试。

## 平台边界

- helper 必须无业务归属，不读取仓储、安全、设备、HR、质量等模块配置。
- 禁止新增统一配置表保存各业务模块的 App ID、App Secret、token、app_token 或 table_id。
- 禁止通过 `get_settings()` 或其他全局配置替业务模块决定凭证来源。
- 禁止从本目录反向导入 `app.modules.*`。
- 平台层不持久化业务同步状态，也不决定 token 缓存和刷新策略；确需平台级缓存时必须有明确跨模块契约和安全设计。
- 解析完整多维表格链接、`app_token:`、`table=tbl...` 等输入时，优先复用本目录既有解析函数。

## 模块集成方式

业务模块必须在自己的目录中读取、解密和校验配置，再将显式参数传给平台 helper。事件订阅、卡片审批、多维表格同步、字段映射和失败恢复等业务流程留在所属模块。

禁止任一模块直接复用另一个模块的配置表、service、handler 或同步逻辑。可复用部分必须先证明无业务归属，再以最小接口下沉到平台层。

## 安全与验证

- 日志、异常和审计不得记录明文 secret、token、password、key 或完整授权响应。
- 外部调用必须有超时、错误映射和必要的重试边界；写操作不得无界重试。
- 修改公共 helper 时检查所有调用方，并为解析、鉴权失败、超时和第三方异常补相关测试。
- 新增环境变量时遵守根规范和后端规范，将变量同步到工作区根目录 `.env.example` / `.env.local.example`。
