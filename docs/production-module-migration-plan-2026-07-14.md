## 1. 结论与目标

本次不是把外部目录整体复制进平台，而是把其业务能力迁入现有 `production` 模块。平台已有批次、计划、工艺规程、生产记录、物料平衡、标签复核、压差统计和生产飞书配置的基础实现；外部代码补充了车间视图、203 提炼工序链、销售执行计划、发酵/种子培养、生产日志和按目标同步的飞书能力。

迁移完成后，生产人员应能在一个生产模块内完成：计划与销售执行、按生产线管理批次、203 工序执行与进度、发酵与生产日志、受控飞书导入，以及现有标签复核和压差统计。所有写入应可审计、可追溯、可回滚。

## 3. 现状与差异

外部快照包含 97 个生产后端 Python 文件、38 个生产页面和 25 个前端 action，但没有 Alembic migration、数据库导出或附件导出。平台已存在生产 schema、`production.feishu_configs` 加密配置、压差与标签复核 API；其生成的 OpenAPI 尚未包含外部的发酵、203 工序、日志与销售执行接口。

三项必须先遵守的兼容约束：

1. **计划模型不兼容**：平台使用“计划头 + PlanTask”，外部将车间、产品、日期、产量、安环、质量直接放在 `production_plans` 行中。不得用外部模型覆盖已有表。
2. **车间编码不兼容**：平台使用 `103-1`、`103-2` 等生产线编码；外部将 103 按产品页面拆分。必须先固化产品—车间—生产线映射。
3. **飞书配置不兼容**：平台已有 `production.feishu_configs`，外部使用另一张 `production_feishu_configs` 表和前端 localStorage 保存 App Secret。迁移时保留平台加密配置，严禁浏览器缓存密钥。

## 4. 目标业务模型

### 4.1 计划与销售执行

```text
ProductionPlan（现有月度计划头）
  └─ PlanTask（现有任务/批次安排）

ProductionExecutionPlan（新增独立台账：车间、产品、日期、计划/实际产量、安环、质量、来源）

SalesPlanDetail（新增：发货、开票、库存、产能、完成率、来源）
```

- `ProductionExecutionPlan` 独立承载外部行式业务字段，不改变既有计划编号、任务和状态含义。
- `SalesPlanDetail` 保留外部 14 个销售执行指标；首期来源为手工录入或飞书，后续再与仓储/财务通过各模块 `public_api.py` 协同。
- 所有同步数据保留 `source`、外部记录标识、同步时间和冲突状态；手工修订不得被下一次同步静默覆盖。

### 4.2 工艺与车间

批次是工艺记录的共同业务锚点。203 车间按以下顺序展示并记录：发酵液接收、预处理、陶瓷膜过滤（进料、运行、清洗、分离、设备）、一次脱色/板框/浓缩/离心、二次重结晶脱色/板框/浓缩/离心、烘干、包装。

每类记录均应带批次或批号、记录时间、操作人、来源、飞书记录标识和软删除标记。新表不新增数据库外键；跨表关联由 UUID/业务编号和 Service 校验维护。

### 4.3 飞书同步

```text
production.feishu_configs              已加密的应用凭据（现有）
production.feishu_sync_bindings        新增：sync_target、产品/车间、table_id、字段映射、启用状态
production.feishu_sync_runs            新增：发起人、时间、结果、行数、错误摘要、幂等键
```

- 凭据由生产模块读取和解密后，显式传入平台飞书 helper；平台层不感知生产业务。
- 每个绑定只同步一个明确业务目标，按 `feishu_record_id` 或业务唯一键 upsert。
- 同步失败不得影响已保存的手工数据；结果和异常写入生产审计/同步运行记录，日志中不得出现密钥或 token。

## 6. 数据迁移策略

外部目录不含源库数据，因此数据切换必须在获得源 PostgreSQL 只读导出、附件清单和飞书历史表范围后进行。

1. **盘点与冻结**：输出源/目标表清单、行数、日期范围、主键、`feishu_record_id`、附件地址和敏感字段说明；在切换窗口冻结源端写入。
2. **映射与演练**：先导入隔离测试库，生成产品—车间—生产线映射和计划字段映射；无法映射的数据进入异常清单，不丢弃、不强行导入。
3. **幂等导入**：以源 UUID、飞书记录 ID 或经确认的业务复合键去重；每批导入写入批次号、校验和、开始/结束时间和异常计数。
4. **对账验收**：逐表核对行数、唯一键、关键金额/数量聚合、批次工序覆盖率和随机字段样本；附件以可访问率和抽样哈希核验。
5. **灰度切换**：先启用只读查询和飞书预览，再开放单车间写入，最后切换全模块；源系统保留只读回查窗口与回滚导出。

## 8. 技术与安全红线

- 不直接复制来源的 `db.refresh()` 写法；新增/更新遵守异步 `flush` 与 eager re-fetch 规则。
- 不复制来源中直接读取 AI 环境变量的标签复核实现；继续使用 `app.core.llm.llm_client`。
- 不复制来源前端的手写 API DTO、`Record<string, unknown>` 写入载荷或 localStorage App Secret。
- 每次 API 变化必须导出后端 OpenAPI，并执行前端 `pnpm generate:api`；每次模型变化必须有已审查的 Alembic migration。
- 不导入外部独立压差工程，不删除现有嵌入目录；其后续清理需单独立项。

## 9. 需业务负责人确认的决策

1. 生产计划执行明细是挂在现有计划头下，还是以月度计划自动建立计划头；本计划默认前者。
2. 103 车间产品对应的平台生产线编码，以及 203 车间的有效批次/产品范围。
3. 销售执行字段的最终权威来源：首期飞书/手工，后续是否由仓储发货和财务开票自动回填。
4. 各 `sync_target` 的飞书表、字段映射、同步频率、冲突处理人和数据保留期限。
5. 历史数据、附件和飞书数据的可用导出方式及灰度车间顺序。
