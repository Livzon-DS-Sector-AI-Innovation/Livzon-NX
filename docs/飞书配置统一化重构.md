# 统一飞书只读数据、展示页面、概览与 AI 分析方案

## Summary

- 每个模块保留一个飞书配置入口，统一使用相同组件；每模块首版一组 `App ID/Secret`，可配置多个 Wiki 和多维表格入口。
- 飞书数据每日完整同步到模块本地镜像，页面、图表、算法和 AI 均只读取本地镜像，不在用户访问页面时调用飞书。
- 普通数据页面使用统一 `MappedDatasetPage` 构建，只需传入稳定 `pageKey`，即可展示该页面绑定的一张或多张飞书表。
- 多表页面使用页签，映射采用点击多选；所有飞书字段均可访问，前端根据字段元数据动态渲染，不写死列。
- 概览/总览页面按模块代码定制，但复用统一的数据集查询接口、图表组件和分析服务，不建设低代码拖拽大屏。
- 分析采用“确定性统计/算法先计算，LLM 再解释”的方式；支持用户点击和同步后自动触发，Prompt 在配置页版本化管理。
- 原始行允许进入 LLM，但必须经过字段白名单、相关行筛选、脱敏、条数和 Token 上限控制。
- 映射表只读飞书，不调用任何多维表格写接口。

## Key Changes

### 1. 统一模块飞书配置页面

每个模块原“飞书配置”路由继续保留，但统一渲染 `ModuleFeishuDataSourcePage(moduleCode)`，包含：

1. **应用凭据**
   - App ID、App Secret、启用状态、每日同步时间、备注。
   - Secret 加密保存，只允许覆盖，不返回明文。
   - 保存和连接测试分离，避免保存后立即触发长时间同步。

2. **数据入口**
   - 一组凭据下添加多个 Wiki/Base。
   - 支持添加、测试、重新发现、停用和软删除。
   - Wiki 按节点递归发现；遇到 `obj_type=bitable` 时使用 `obj_token` 继续获取 Base 内所有数据表。
   - Base 数据表目录按飞书 `page_token` 分页拉取，单页最大 100。[飞书列出数据表](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table/list?lang=zh-CN)

3. **资源目录**
   - 按“入口 → Wiki 路径 → Base → 数据表”显示。
   - 展示字段数、记录数、revision、最近发现、最近完整同步、结构变化和权限状态。
   - 支持查看字段和前 20 条本地镜像预览。

4. **页面映射**
   - 左侧选择当前模块菜单页面。
   - 点击“添加数据表”，在抽屉中搜索和多选。
   - 配置页签名称、顺序、默认页签、显示字段、默认排序和历史保留策略。
   - 草稿预览后发布；发布、修改和解绑写审计。

每个模块仍在自己的 schema 保存连接、资源和镜像；平台飞书层只接收调用方显式传入的凭据和 token，不读取模块配置。

### 2. 统一纯数据展示页面

新增统一页面组件 `MappedDatasetPage`。只展示飞书数据的菜单页面使用轻量包装：

```tsx
export default function Page() {
  return <MappedDatasetPage pageKey="warehouse.raw_material" />
}
```

统一页面由以下部分组成：

- 页面标题、数据更新时间、同步状态和数据来源路径。
- 多数据表页签；最多直接显示 6 个，其余进入“更多”。
- 搜索、字段筛选、排序、刷新本地数据、列设置。
- 动态表格、空数据、同步失败、无权限、结构变化状态。
- 字段详情抽屉，用于展示附件、关联记录、人员、多值字段和复杂 JSON。
- 服务端分页；单页默认 50，允许 20/50/100。
- 未激活页签不请求数据，切换后按需加载。
- 当前页签写入 `?dataset=<binding_id>`，刷新和分享链接后保持选择。

“完整显示”定义为：

- 飞书返回的每个字段都保存在镜像中，并可通过列设置显示。
- 默认根据页面宽度展示高优先级字段，其余字段不丢失，可横向滚动或从列设置启用。
- 表格使用固定表头、横向滚动和纵向虚拟化，避免 100 多列或大页数据卡顿。
- 字段以 `field_id` 作为稳定键，字段名称仅用于显示；飞书改字段名不会造成数据错列。
- 单元格接口返回结构化值，不在后端提前拼成不可逆字符串。
- 附件和临时 URL 不长期缓存可访问地址，只保存飞书附件标识和安全元数据；下载时通过权限校验后的后端接口获取。

统一字段渲染器覆盖：

- 文本、数字、日期时间、复选框。
- 单选、多选、人员、部门。
- URL、附件、电话、地理位置。
- 单向/双向关联记录。
- 公式、查找引用和飞书复杂对象。
- 未识别字段类型降级为摘要加 JSON 详情，不导致整个页面失败。

### 3. 本地镜像与查询接口

每个模块使用标准化逻辑模型：

- `feishu_connection`
- `feishu_source_roots`
- `feishu_resources`
- `feishu_resource_fields`
- `feishu_page_bindings`
- `feishu_sync_runs`
- `feishu_mirror_records`
- `feishu_record_snapshots`
- `feishu_analysis_profiles`
- `feishu_prompt_versions`
- `feishu_analysis_runs`
- `feishu_analysis_results`

镜像记录至少保存：

```text
resource_id
record_id
raw_fields JSONB
normalized_fields JSONB
search_text
source_created_time
source_modified_time
source_revision
mirror_version
is_source_deleted
synced_at
```

`normalized_fields` 按字段类型保存可排序、可筛选的规范值；`raw_fields` 保留完整原始响应。通用查询层只能操作资源目录中已登记的 `field_id`，不允许客户端提交任意 SQL 或 JSON 路径。

统一页面接口：

```text
GET /api/v1/{module}/page-data/{page_key}
GET /api/v1/{module}/page-data/{page_key}/{binding_id}/records
GET /api/v1/{module}/page-data/{page_key}/{binding_id}/field-values
GET /api/v1/{module}/page-data/{page_key}/{binding_id}/record/{record_id}
```

记录查询参数：

```text
page
page_size
keyword
filters[field_id, operator, value]
sort[field_id, direction]
snapshot_at
```

响应包含：

```json
{
  "dataset": {
    "binding_id": "...",
    "resource_id": "...",
    "title": "...",
    "source_path": [],
    "last_complete_sync_at": "...",
    "sync_status": "success"
  },
  "fields": [],
  "records": [],
  "pagination": {
    "page": 1,
    "page_size": 50,
    "total": 1000
  }
}
```

页面读取流程始终为：

```text
浏览器 → Next.js → 模块页面数据 API → PostgreSQL 本地镜像
```

页面访问不等待飞书、不消耗飞书 QPS，也不会因为飞书临时故障而无法显示上一次完整数据。

### 4. 完整同步与飞书接口控制

同一张表不使用多线程分段。飞书记录分页依赖上一页返回的 `page_token`，旧列出记录接口单页最多 500 条；官方同时提示同一文档并发读取多表可能导致阻塞。[记录分页与限制](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/list)、[多维表格接入限制](https://open.feishu.cn/document/server-docs/docs/bitable-v1/notification)

同步流程固定为：

1. 对 `resource_id` 获取分布式锁。
2. 创建 `sync_run`，记录开始 revision、schema hash 和开始时间。
3. 获取字段元数据。
4. 使用 `page_size=500` 串行消费 `page_token`；响应过大或超时时降到 200、100。
5. 每页写入当前运行 staging，使用 `resource_id + record_id` 去重。
6. 失败重试时从第一页开始，不依赖可能失效的历史 page token。
7. 遍历完成后校验唯一记录数、total、空 ID、重复 ID、页链完整性和结束 revision。
8. 同步期间 revision 变化时最多重新稳定化读取两次。
9. 校验通过后原子发布新 `mirror_version`；页面此前始终读取旧完整版本。
10. 只有完整同步成功后，才把新版本缺失的旧记录标记为源端删除。
11. 更新资源状态并触发概览聚合和配置为自动执行的分析任务。

并发策略：

- 同一 Base：并发 1。
- 同一连接的不同 Base：最多并发 2。
- 每个 App 使用共享令牌桶，默认 5 QPS。
- 429、`1254290`、5xx 和超时采用指数退避加随机抖动，最多 6 次。
- 每日任务按 Base 错峰。
- 手动同步进入同一队列，不绕过限流、锁和完整性校验。

### 5. 概览与总览页面

概览页面按模块代码定制，不使用拖拽式页面生成器。统一复用：

- `OverviewPageShell`
- `MetricCard`
- `TrendChart`
- `DistributionChart`
- `RankingChart`
- `DataQualityCard`
- `AnalysisPanel`
- 日期范围、数据集范围和维度筛选器

图表统一使用项目现有 ECharts 技术栈。

每个模块注册自己的分析数据集：

```text
dataset_key
resource_ids
time_field
metric_fields
dimension_fields
unit
aggregation
default_time_range
quality_rules
```

通用聚合接口：

```text
POST /api/v1/{module}/analytics/query
GET  /api/v1/{module}/overview/{overview_key}
```

支持的基础能力：

- `count`、`count_distinct`
- `sum`、`avg`、`min`、`max`
- 按天、周、月分组
- 同比、环比
- Top N、分类分布
- 缺失率、重复率、异常值数量
- 多数据表联合汇总，但只允许分析配置中明确登记的关联键和字段

概览 API 在 PostgreSQL 中完成过滤和聚合，只返回图表所需数据点，不把全量明细发送给前端。

模块定制页面负责业务口径，例如：

- 能源：消耗量、单耗、车间分布、环比趋势。
- 质量：偏差数量、CAPA 超期、风险级别分布。
- 仓储：库存量、呆滞品、临期趋势。
- 生产：批次数、产量、异常批次和工序趋势。

数据表字段不足或类型不满足配置时，概览返回 `configuration_invalid`，明确指出缺少的时间、指标或维度字段，不输出误导图表。

### 6. 算法与 AI 分析

分析分为三层：

1. **数据质量层**
   - 缺失、重复、类型异常。
   - 时间断点、异常突增突降。
   - 样本量和时间跨度是否足以分析。

2. **确定性算法层**
   - 描述统计、同比、环比、移动平均。
   - IQR/MAD 异常值检测。
   - 线性趋势和斜率。
   - 变点检测和周期性提示。
   - 基于模块配置阈值的风险规则。
   - 可行性分析所需的业务约束、阈值和评分规则由模块策略实现，不能由通用 LLM 凭空决定。

3. **LLM 解释层**
   - 使用系统设置中的统一 LLM 配置和 `llm_client`。
   - 输入算法结果、指标摘要、证据以及受控原始行。
   - 输出可行性、风险、趋势、原因、建议、置信度和证据引用。
   - AI 结论只作为辅助研判，不自动触发审批、生产调整或其他业务写操作。

支持两种触发方式：

- 用户点击“生成分析”。
- 数据集配置为自动分析时，在每日完整同步和聚合成功后触发。

采用异步任务接口：

```text
POST /api/v1/{module}/analysis/profiles/{profile_id}/run
GET  /api/v1/{module}/analysis/runs/{run_id}
GET  /api/v1/{module}/analysis/profiles/{profile_id}/latest
```

分析结果保存：

```text
profile_id
source_resource_ids
source_mirror_versions
algorithm_version
prompt_version
llm_config_id
trigger_type
status
metrics
risks
trends
feasibility
recommendations
evidence
confidence
created_at
```

因此每个结论都能追溯到具体镜像版本、Prompt 版本和算法版本。

### 7. Prompt 与原始数据治理

Prompt 在模块飞书配置页增加“分析配置”区域：

- 分析名称、适用数据表、分析目标。
- 系统 Prompt、业务背景、关注点。
- 输入字段白名单。
- 输出 JSON Schema。
- 自动触发开关。
- 发布、历史版本、对比和回滚。
- 草稿 Prompt 不参与正式自动任务。

原始行进入 LLM 前必须：

- 先由本地算法筛选近期、异常、边界和代表性记录。
- 默认最多 100 行；单个 Profile 可在 20–200 范围配置。
- 仅发送字段白名单中的数据。
- 密码、Secret、Token、Cookie 等字段无条件排除。
- 人员、电话、邮箱等敏感字段默认脱敏；确需发送时增加单独权限开关和审计。
- 根据模型上下文预算裁剪，绝不“尽量塞入全部数据”。
- 飞书单元格内容按不可信输入处理，用明确数据边界包裹，禁止其中的文本改变系统指令。
- LLM 输出必须通过 Pydantic/JSON Schema 校验；失败时最多修复一次，仍失败则保留算法结果并标记 AI 解释失败。

分析页面必须区分：

- 已验证事实。
- 算法检测结果。
- AI 推断。
- 数据不足或低置信度结论。

### 8. 迁移与实施顺序

1. 建立统一模块模型、同步引擎和页面数据 API。
2. 抽取现有仓储动态字段渲染能力，完成 `MappedDatasetPage`。
3. 以仓储验证多 Base、多表页签和大宽表；以能源验证 Wiki 递归、历史快照和趋势。
4. 建立统一聚合接口和概览组件库；保留各模块概览代码定制。
5. 建立分析 Profile、Prompt 版本和异步分析任务。
6. 接入系统 LLM 配置，实现点击与同步后自动分析。
7. 迁移生产、质量及其他模块，旧配置页改为统一组件。
8. 新旧同步并行至少 7 个每日周期，比较资源数、字段数、记录数和抽样 hash。
9. 完成 OpenAPI、前端类型和 Alembic migration 后再停止旧读取接口。

## Test Plan

- 一组凭据配置多个 Wiki/Base，完整发现所有嵌套多维表格和数据表。
- 500、501、10,000、20,000 条记录验证分页、计数、去重和原子发布。
- 分页期间源表变化、进程退出、Token 失效、429、超时和无权限时不发布半成品。
- 1、6、7 张绑定表验证页签、更多菜单、URL 状态和按需加载。
- 150 个字段验证完整字段保留、列设置、横向滚动和虚拟化性能。
- 所有飞书字段类型验证动态渲染及未知类型降级。
- 搜索、动态字段筛选、日期/数字排序和服务端分页结果正确。
- 页面访问过程中飞书不可用时仍显示最后完整镜像和过期提示。
- 概览聚合与镜像明细人工核对一致；时间字段、单位或数据不足时明确拒绝分析。
- 趋势、同比、环比、异常检测使用固定数据集验证算法结果。
- AI 点击触发、自动触发、并发任务、失败重试和结果追溯正确。
- Prompt 发布、回滚后新运行引用正确版本，历史结果不被重写。
- 原始行只包含白名单字段，敏感字段脱敏，条数和 Token 上限生效。
- 源数据包含提示注入文本时不能改变系统 Prompt 或输出 Schema。
- AI 不可用或输出非法时，概览和确定性算法结果仍正常展示。
- 验证 Secret、Token 和敏感原始数据不会进入普通日志与审计摘要。
- 后端运行相关 pytest、ruff、mypy；前端运行 typecheck、lint、build；API 变更后运行根目录 `scripts/generate-api.ps1` 并检查无关生成漂移。

## Assumptions

- 每模块首版一组 App ID/Secret，可配置多个 Wiki/Base。
- 配置页面保留在模块内，但组件和交互完全统一。
- 数据映射采用点击多选；多表展示采用页签。
- 默认每日定时同步，并支持手动同步。
- 普通数据页读取本地镜像，不实时访问飞书。
- 概览页面由各模块代码定制，但复用统一查询接口和图表组件。
- AI 使用系统统一 LLM 配置；Prompt 在配置页版本化维护。
- AI 支持手动和自动触发。
- 原始行允许发送给 LLM，但只能发送本地算法筛选后的相关行，并受字段白名单、脱敏、条数和 Token 预算约束。
- 飞书多维表格在该能力中严格只读；AI 分析不自动执行任何业务写操作。
