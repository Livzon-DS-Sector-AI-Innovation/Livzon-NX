# 能源管理模块：飞书 Wiki 数据归档与分析方案

> 状态：实施与数据库验证完成；真实飞书联调待外部前置条件
> 创建时间：2026-07-13
> 对应任务账本：`docs/tasks/energy-wiki-management-tasks-2026-07-13.md`

## 1. 目标与范围

能源模块以飞书 Wiki 中的电子表格为唯一新增数据来源，只读取并持久化数据，不向飞书写入任何内容。

- 从配置的 Wiki 父根目录递归发现历史及未来月份的数据表。
- 原样归档总表、分表、子表和每个工作簿内的工作表；每日内容变化时保留不可变快照。
- 管理员为明细表配置字段映射后，平台提供按能源类别与单位隔离的分析看板。
- 旧第三方设备采集、设备配置、预警和采集日志 API/UI 下线；历史数据库表保留，不执行删除或迁移。

## 2. 数据与同步设计

### 2.1 能源模块内的数据实体

所有新增实体位于 `energy` schema，继承共享 `BaseModel`，使用软删除与显式索引；业务关联只保存 UUID，不创建数据库外键。

| 实体 | 职责 |
| --- | --- |
| `EnergyFeishuConfig` | 模块独立的飞书 App 凭据、Wiki 根链接、每日同步设置与启用状态 |
| `EnergyWikiDocument` | 已发现的 Wiki 节点、层级路径、真实文档 token 与归档月份 |
| `EnergyWorkbookSheet` | 文档内工作表、表头、结构指纹、映射状态与最近快照 |
| `EnergySyncRun` | 手动/自动同步的计划窗口、状态、计数、脱敏错误与幂等键 |
| `EnergySheetSnapshot` | 某工作表发生变化时产生的不可变快照 |
| `EnergySnapshotRow` | 快照的原始单元格行数据与行哈希，供分页浏览 |
| `EnergySheetMapping` | 明细表字段映射及版本 |
| `EnergyMetricFact` | 映射后可分析的数值事实数据 |

App Secret 通过 `app.core.secrets` 加密保存，所有 API 和日志仅暴露掩码。原始数据保留单元格值，不解析样式、图片、合并单元格或附件。

### 2.2 发现与归档流程

1. 用模块配置的凭据解析 Wiki 根节点，递归分页读取所有后代节点。
2. 从节点标题或最近的祖先标题识别 `YYYY年M月`、`YYYY-MM`、`YYYY.MM`；无法识别的文档仍归档，状态为未分类，不进入看板。
3. 对每个 `sheet` 文档读取工作簿元数据及所有工作表。用户提供 URL 中的 `sheet` 参数仅定位一个工作表，首次同步仍归档该工作簿内全部工作表。
4. 读取行式表数据，生成规范化内容哈希。哈希无变化时只记录同步成功；有变化时写入一份新快照和快照行。
5. 仅启用映射的明细表生成事实数据。相同结构指纹的新表自动继承映射；结构变化则保留原始数据并标记为待映射。

### 2.3 可靠性

- 默认每日 `02:00 Asia/Shanghai` 同步，调度器每 15 分钟扫描到期配置；当日计划未成功时自动补偿。
- 自动同步窗口使用稳定幂等键和数据库领取锁，避免多实例重复执行。
- 对网络、限流与 5xx 最多重试三次并指数退避；权限和字段错误记录为可处理失败，不重复请求。
- 同步运行逐工作表隔离失败，整次运行可为 `success`、`partial` 或 `failed`。

## 3. 映射与分析规则

首期仅支持“表头行 + 后续明细行”。管理员在来源详情中配置：表头行、日期列、可选维度列、一个或多个数值列、能源类别、单位、计量点和数值口径。

- **期间消耗量**：在查询区间内直接求和。
- **累计表底**：按同一计量点计算期末读数减期初读数；负差值标为异常，不计入汇总。
- 总表和汇总表默认不启用分析，避免与分表/子表重复统计。
- 看板始终使用每张工作表的最新快照；历史快照仅用于溯源浏览，不参与重复累计。
- 汇总键固定为“能源类别 + 单位”，禁止跨单位合计。

### 3.1 本工作簿的三层来源关联

根据已提供的工作簿结构，工作表按角色而不是按相同列结构关联；每张工作表均原样归档，并在映射时显式选择角色：

| 工作表集合 | 映射角色 | 数据含义 | 默认看板行为 |
| --- | --- | --- | --- |
| `日总量` | `daily_summary` | 全厂日总量（如蒸汽日产气量、电日用量、饮用水日总量） | 只做核对，不参与默认汇总 |
| `电量`、`饮用水量`、`蒸汽量`、`冰水量`、`空气量`、`循环水量` | `energy_summary` | 某一能源按车间、公共区域或计量点展开的日汇总 | 只做核对，不参与默认汇总 |
| `101车间`、`102-1车间`、`103-1车间` 等 | `workshop_detail` | 一个车间每天实际拥有的能源字段 | 默认统计来源 |

`workshop_detail` 映射将工作表标题写入固定维度 `车间`，例如 `101车间` Sheet 中的 `日期 / 饮用水 / 电 / 蒸汽 / 压缩空气 / 7°C冷水 / 循环水` 会拆成同一天、同一车间下的多个能源事实。某车间没有“冰水量”或“循环水量”列时不补零、不猜测，只不产生该能源事实。

`energy_summary` 映射按列把“101车间、办公楼、液体库”等写入同一 `车间/区域` 维度；`daily_summary` 按能源类别保存全厂值。两类汇总事实保留用于“明细合计 vs 分表 vs 日总量”的差异校验，默认不能直接叠加到 `workshop_detail`，从而避免三层重复统计。未来如某公共区域没有车间明细，可由管理员明确将该列设为共享明细来源，而非隐式参与汇总。

所有事实的业务关联键为：`日期 + 能源类别 + 单位 + 车间/区域 + 计量点`。映射版本、快照版本和来源角色同时保留，既能回溯原始单元格，也能解释某日某车间为何没有某一能源。

## 4. API 与前端

新增资源包括：飞书配置与连通性、同步触发与运行日志、来源树、快照与原始行、映射预览与保存、能源总览。

前端保留 `/energy` 为总览，并新增：

- `/energy/sources`：飞书配置、来源树、映射状态和手动发现。
- `/energy/sources/[sheetId]`：字段映射、预览与数据质量反馈。
- `/energy/data`：按月份、文档、工作表和快照分页浏览原始数据。
- `/energy/sync-runs`：自动/手动运行记录、错误和重试入口。

所有写操作通过 Server Actions，API 类型由后端 OpenAPI 生成；运行时取数页面声明 `dynamic = 'force-dynamic'`。

### 4.1 运营总览与动态导航（2026-07-13）

`GET /api/v1/energy/overview` 以 `source_scope` 明确三层统计边界：`daily_summary`（日总量）、`energy_summary`（能源分表）和 `detail`（车间/共享明细，默认）。查询可传 `workshop`，只匹配事实维度中的“车间”；也可传 `source_sheet_title`，只读取指定分表。每次响应返回各指标的 `metric_key`、最新有效日期和 `latest_metrics`，其中百分比或名称含“占比”的指标只作为最新日状态返回，绝不参与期间求和、趋势或排行。

`/energy` 同时请求默认车间明细和日总量：日总量作为全厂 KPI，车间明细作为趋势、排行与明细拆解；能源分表和车间入口均复用这一页面的 URL 查询参数。侧边栏仅从“已映射”来源生成动态分组：来源角色为 `energy_summary` 的 Sheet 进入“按能源”，`workshop_detail` 的 Sheet 进入“按车间”。无映射来源时不显示动态分组；日期范围和既有能源类别筛选会保留。

看板的 KPI 卡片始终保留单位，趋势序列也以“指标 + 单位”区分，禁止跨单位累加；车间不存在的字段显示为空，不用零值替代。页面使用 ECharts 绘制趋势和排名，提供加载骨架、同步/映射未完成空态和请求失败态。

## 5. 外部前置条件

当前提供的链接是月度叶子表。上线配置必须提供包含各月份节点的 Wiki 父根目录链接，否则无法发现未来月份。

飞书自建应用必须获得 Wiki 节点、子节点和电子表格读取权限，并被授予实际知识库及文档访问权。同步先由 Wiki 节点获得真实文档 token，再读取电子表格数据：

- [获取知识空间节点信息](https://open.feishu.cn/document/server-docs/docs/wiki-v2/space-node/get_node)
- [获取知识空间子节点列表](https://open.feishu.cn/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/wiki-v2/space-node/list)
- [电子表格概述](https://open.feishu.cn/document/ukTMukTMukTM/uATMzUjLwEzM14CMxMTN/overview)

## 6. 验收标准

1. 配置父根链接和凭据后可验证连通性、发现历史月份并回补快照。
2. 无变化的同步不会重复创建快照；数据回退到旧值时仍产生新的时间序列快照。
3. 新月份自动发现，结构相同的明细表继承映射；未知结构仅归档并提示待处理。
4. 总表、分表、子表可分别浏览，未映射汇总表不影响看板结果。
5. 直接值和累计值按既定口径正确计算，跨单位不合计，负差值可追溯。
6. 凭据不出现在响应、日志或审计载荷；同步失败可定位并手动重试。
