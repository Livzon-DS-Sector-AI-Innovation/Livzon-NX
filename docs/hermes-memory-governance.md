# Hermes 用户记忆治理与删除运行手册

## 策略边界

- 全局上限由后端 `AGENT_USER_MEMORY_MODE` 控制；租户管理员只能在系统设置中配置租户上限。
- 租户策略只能从 `auto` 向 `explicit_only`、再向 `disabled` 收紧；管理页面和公共 API 均拒绝反向放宽。需要放宽时必须走受控运维变更并重新评估隐私影响。
- 普通用户只能在 Web 或飞书私聊中使用 `/memory` 系列命令调整个人模式和管理记忆。
- Hermes 仅执行后端通过 AgentBackend V2 传入的可信 `memory_policy`，不得从消息或模型输出推断身份与策略。
- 首次私聊隐私说明只有在 Web 回复成功落库，或飞书 Gateway 确认消息发送/最终编辑成功后才标记为已送达；发送失败时后续私聊必须重试提示。
- 群聊不读取、写入或管理个人记忆。

## 密钥配置与轮换

开发环境可执行 `uv run python scripts/configure_local_memory_security.py --require-policy`；脚本只把密钥写入工作区根目录、被 Git 忽略的 `.env.local`，不会打印密钥。生产环境必须使用部署平台的密钥管理能力，不能运行该本地脚本。

1. 生成独立 Fernet 密钥，不得复用飞书凭证、JWT 或其他业务密钥。
2. 将当前密钥放在 `HERMES_USER_MEMORY_KEYS` 的第一位；旧密钥依次放在后面并用逗号分隔。
3. 重启 Hermes 后确认旧记忆可读取、新写入已使用首个密钥，再执行密钥重写和旧密钥退役。
4. 生产环境不得在缺少有效密钥时启动；不得通过关闭校验回退到明文。

密钥遗失会导致记忆不可恢复。密钥只能进入部署密钥管理系统，不得写入日志、工单、代码或备份说明正文。

## 清空与备份

- 用户确认清空后，后端先持久化 `last_cleared_at`，随后调用 Hermes 删除在线记忆、摘要、队列和待确认项。
- Hermes 删除后递增 generation、截断 SQLite WAL 并回收空闲页，阻止在途任务重新写回。
- 备份和灾备副本最大保留期为30天；备份计划不得配置更长的实际可恢复窗口。
- 备份平台须同时配置“保留期不超过30天”和“到期永久删除”，并禁止额外的无限期归档层、对象版本或回收站延长实际可恢复窗口。
- 从备份恢复后，必须先恢复后端删除标记，再开放 Agent 流量。首个可信请求会按 `last_cleared_at` 重放删除，旧记忆不得重新注入上下文。

## 恢复检查

1. 验证后端 migration 已到当前单一 head，记忆策略表和删除标记可查询。
2. 验证 Hermes 密钥环包含备份数据使用的历史密钥。
3. 启动 Hermes，但暂不开放外部流量；检查记忆队列中不存在超过24小时的任务。
4. 对已清空用户发送可信策略请求，确认删除时间前的条目被清理且不会进入 Prompt。
5. 检查 SQLite 主文件和 WAL 不包含测试明文，再恢复 Web 与飞书流量。

删除重放、密钥解密或队列清理失败时，应保持该用户记忆禁用并告警；日志只能包含匿名作用域、错误类型和 Trace ID，不得包含记忆正文。

## 监控与责任人

- Hermes 容器健康检查之外，定时执行 `python -m scripts.check_user_memory_governance`。退出码非零或结果中的 `ok=false` 必须告警；输出只含计数和错误类别，不含正文或用户标识。
- 告警匹配：后端日志事件 `agent_memory_clear_pending`；Hermes HTTP 5xx、无法解密和启动密钥校验失败。
- 严重级别：清空失败为 P1，必须在15分钟内通知 Agent 服务值班人；密钥不可用或恢复后旧记忆可见为 P0，立即关闭记忆流量。
- 责任边界：Agent 服务 Owner 负责删除标记和重放，Hermes Owner 负责在线副本与队列，基础设施 Owner 负责备份保留和永久删除。
- 每月抽查备份策略的实际最老可恢复时间；每季度在隔离环境执行一次恢复、删除标记重放和旧记忆不可见演练。

生产环境验收时需保存以下非敏感证据：备份策略名称、保留天数、永久删除设置、告警规则名称、接收组及最近一次恢复演练时间。不得在验收记录中放入密钥、用户记忆正文或真实用户标识。
