# 页面级最小授权：核心规则与验收

本文件约束权限核心，不要求业务模块在功能稳定前完成接入。2026-08-31
完成本轮核心收尾；模块接入、审批资格及实际业务数据验收另行实施。

## 授权边界

- 普通用户按有效菜单页面独立授权。角色取并集；用户 custom 完整替换角色结果，
  空覆盖明确拒绝；inherit 恢复角色基线。
- 操作包含查询和访问，查询包含访问。高风险子动作必须独立选中，同时满足操作权限。
- 最小单位是页面内的权限类别，不是所有普通按钮。已获得某页“操作”的用户，
  可以执行该页后来正确登记的普通操作；新增高风险动作不随“操作”自动授权。
- 系统管理员全权限是明确例外，不受用户页面覆盖限制；权限不替代审批岗位、
  人工责任、业务状态和二次确认。普通权限经办人不能通过所属角色修改自身授权。
- 数据范围编辑入口继续隐藏。已有范围事实与后端限制保留，不自动扩大普通用户范围。
- 强制模式默认拒绝未授权页面、未登记接口和伪造页面上下文。草稿仍执行旧规则，
  不得把“配置已保存”等同于“全模块已按新规则执行”。

## 页面与动作生命周期

`dazah-backend/app/platform/identity/page_permission_lifecycle.json` 是独立于
生成菜单的历史登记簿，不得根据当前菜单重新生成来抹除已退役条目。

| 变更 | 标识与授权处理 |
| --- | --- |
| 修改中文名称、图标、显示排序 | 保持标识与既有权限，不因文案改变重新授权 |
| 暂时停用菜单或其父目录 | 暂停有效授权，保存事实；明确恢复同一功能后恢复原授权 |
| 删除数据库菜单 | 软删除并保留唯一标识，不允许用旧标识重新创建菜单 |
| 业务页面永久下线 | 同步移除策略/入口，登记簿页面状态改为 retired；保留历史条目 |
| 页面重做、改变模块或路由 | 使用新 page_key，旧页面退役；不自动转移角色或用户授权 |
| 新增独立高风险动作 | 登记新的动作 key、类别和 active 状态，默认无该子授权 |
| 移除高风险动作 | 从页面策略移除，登记簿保留动作并设为 retired |
| 高风险动作重做或改变责任含义 | 使用新动作 key，旧动作退役；不继承旧子授权 |

路由改变也按新的授权身份处理。这是保守的安全约束；如需未来支持授权保持型
路由迁移，应单独设计有版本、原因、差异确认和审计的迁移，不直接改登记簿绕过检查。

仅改按钮或动作的中文名称不能证明业务含义未变。代码检查可以识别标识复用、
路由/模块/类别变化及退役恢复，但不能自动判断同一标识背后的业务代码是否被重做。
功能评审必须明确判断“原功能调整”或“新授权身份”；后者必须按上表新建标识。

## 检查与发布

从根目录使用后端 Python 环境执行：

```powershell
dazah-backend/.venv/Scripts/python.exe scripts/check-page-permission-lifecycle.py --base HEAD
```

PR 验收时把 HEAD 换成目标分支的实际 base SHA。后端 CI quality 已调用此检查，
复用现有 CI_BASE_SHA，不新增环境变量。首次加入登记簿的基线可以不存在该文件；
此后禁止删除历史页面/动作、恢复 retired 标识、复用标识修改归属、路由或类别。
同时拒绝重复标识、未登记页面/动作、移除但未声明退役的条目。

运行时也检查登记簿：无效页面不产生普通用户有效授权、不接受新授权，模块发布
列出目录缺口；不是仅依靠 CI 约定。登记簿按代码发布并在进程内缓存，不是后台热编辑配置。
必须与页面策略一起部署并重启服务，不得绕过 CI、手工改库或回滚旧镜像来恢复退役身份。

## 并发与撤权

- 权限管理写请求先取得与管理员升降级相同的数据库事务锁，再重新读取操作者的
  当前状态和管理资格。排队期间被停用或降级的操作者不能沿用旧对象提交。
- 用户、角色及发布记录的加锁查询强制刷新已有会话对象，期望版本比较不使用旧缓存。
- 发布时在同一管理写事务内重新计算预览摘要，再校验发布版本；首次发布也受串行锁保护。
- 批量失效用数据库原子自增授权版本，同时写 outbox。角色删除、旧角色权限和菜单绑定
  修改也执行版本失效。审批权限变更不依赖前端缓存刷新或事件推送成功来放行。
- 审计、授权事实、授权版本和 outbox 共用数据库事务；审计写入失败不提交授权。
- 撤权约束后续鉴权和工具执行，不宣称能撤回已经提交的业务事务或已发送的外部请求。
- Livzon 快照版本包含实际页面策略、接口绑定及完整生命周期目录；策略变更或退役
  会使旧快照失效，执行入口不自动重建放行。部署本轮更新后需重新同步权限快照。
- 紧急回退仅由系统管理员按版本、原因和确认执行；恢复 legacy 可能扩大旧权限，
  不撤销审计、不倒退授权版本，也不自动回填页面授权。

全局管理写锁是现有体系上的保守增量方案，只串行化低频权限配置，不锁普通业务请求。
大规模角色变更仍会批量更新活动用户，性能优化不应破坏版本和审计的一致性。
