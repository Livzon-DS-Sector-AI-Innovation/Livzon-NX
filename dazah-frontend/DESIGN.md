# Dazah 工厂管理后台设计规范

## 1. 产品定位

Dazah 是原料药工厂的综合管理后台，不是营销网站或展示型应用。界面设计按以下顺序取舍：

1. 业务信息准确
2. 操作路径清晰
3. 权限和风险可识别
4. 状态与结果可追踪
5. 信息密度和操作效率
6. 视觉一致性

禁止使用大面积营销 Hero、定价卡、客户 Logo 墙、装饰性插画带或夸张标题来替代实际业务内容。

## 2. 设计事实来源

- 基础组件使用 Ant Design，优先使用组件原生能力。
- 颜色、字号、圆角和组件 token 以 `src/lib/antd-theme.ts` 为唯一事实来源。
- 全局样式以 `src/app/globals.css` 为准。
- 已有模块页面是交互参考，但明显违反本规范的旧页面不得作为新实现模板。

不要在页面中复制整套主题常量。确需新增全局 token 时，先确认多个模块的复用需求，再最小修改主题配置。

## 3. 页面结构

典型管理页按以下顺序组织：

1. 页面标题与必要说明
2. 关键状态、统计或风险提示
3. 查询和筛选区
4. 主操作与批量操作区
5. 表格、列表或业务工作区
6. 分页、结果摘要或操作记录

页面标题使用业务名称，不添加英文营销副标题。统计卡只展示能帮助判断和操作的指标，不为填充版面堆叠数字。

复杂业务按任务流分区，不按视觉装饰分区。常见信息应直接可见，低频高级选项可以折叠。

## 4. 布局与密度

- 桌面端是主要工作环境，优先保证 1280px 及以上宽度的操作效率。
- 页面使用稳定的内容间距，避免大面积无业务意义留白。
- 筛选项较多时使用紧凑网格或可折叠高级筛选，不纵向堆成长表单。
- 操作按钮靠近其影响的数据区域；全局操作、批量操作和行操作必须分组明确。
- 同一页面避免同时出现多个视觉权重相同的主按钮。
- 长内容使用分区、抽屉、标签页或独立详情页，不能仅靠无限加高弹窗承载。

## 5. 表格与列表

表格是台账类页面的默认表达方式，应满足：

- 列名使用清晰中文，单位放在列名或值旁。
- 关键标识、状态和待办信息优先展示；低频字段可隐藏或放入详情。
- 内容可能过长时配置省略、换行、Tooltip 或可展开内容，禁止破坏列宽。
- 数据量较大时使用服务端分页、排序和筛选，不在浏览器一次加载全部记录。
- 宽表应设置横向滚动，并按需要固定标识列和操作列。
- 批量操作只有在选中数据后才可执行，并显示选择数量和适用范围。
- 行操作较多时保留一到两个高频操作，其余收入“更多”。
- 空数据必须区分“当前筛选无结果”“尚未创建数据”和“无权限查看”。

删除、作废、提交、审批、驳回、批量变更等操作必须展示对象、数量和不可逆影响。

## 6. 表单与录入

- 标签使用业务语言，必填项、单位、格式和示例要明确。
- 优先使用适合数据类型的控件，不用普通文本框代替日期、枚举、人员或数值控件。
- 校验错误靠近字段展示；提交失败后保留用户已输入内容。
- 提交期间禁用重复提交，并提供明确进度或处理中状态。
- 长表单按业务阶段或数据主题分组；关键字段不得藏在默认折叠区域。
- 编辑已有数据时，区分不可修改字段、当前值和将要变更的值。
- 离开未保存表单或覆盖他人新版本时，应给出提醒。

弹窗适合短小、单目标操作；字段多、需要对照上下文或存在多阶段流程时使用抽屉或独立页面。

## 7. 状态与反馈

每个异步区域都必须考虑：

- 初次加载
- 局部刷新
- 空数据
- 请求失败
- 权限不足
- 部分成功
- 重试或恢复方式

成功反馈说明完成了什么；失败反馈说明失败对象、可采取的动作和数据是否已保存。不要只显示“操作失败”。

状态不能只依赖颜色表达，必须同时使用中文文本，必要时配合图标。刷新、同步、导入和生成类长任务应展示任务状态、开始时间、完成结果和失败原因。

## 8. 风险、权限与审计

- 无权限时隐藏不应暴露的入口，或禁用入口并说明所需权限；不得让用户操作后才得到模糊错误。
- 高风险操作使用二次确认，确认文案包含动作、对象和影响。
- 审批、驳回、批准等人工责任判断必须让责任人明确作出，不得伪装成普通自动操作。
- 页面涉及关键状态流转时，应展示当前状态、允许的下一步和历史记录入口。
- 审计和日志页面优先展示操作人、时间、对象、动作、结果和失败原因。
- 敏感字段默认脱敏，不在通知、错误详情或前端日志中展示 secret、token、password、key。

## 9. 颜色、文字与图标

- 主色只用于主要操作、当前选中和必要强调，不用于大面积装饰背景。
- 成功、警告、错误、处理中、停用等状态使用稳定的语义映射。
- 同一业务状态在表格、详情、统计和筛选中保持相同文案与语义色。
- 正文和表格文字保持足够对比度；辅助文字不能淡到难以辨认。
- 页面标题、分区标题和正文形成有限层级，不使用 48px、80px 等营销展示字号。
- 图标用于帮助识别操作或状态，不能代替文字标签；同一图标不得表达多个相反动作。

## 10. 响应式与可访问性

- 桌面端保留完整查询、表格和批量操作能力。
- 窄屏优先保留搜索、关键筛选、关键字段、详情查看和必要轻量操作。
- 宽表在窄屏允许横向滚动或转为摘要列表，不强行压缩到不可读。
- 可点击目标应有足够尺寸，键盘焦点清晰，表单标签与控件正确关联。
- 不使用仅在 hover 时才可发现的关键操作或说明。
- 图表必须有标题、单位、图例和可读取的数值替代信息。

## 11. 禁止事项

- 禁止将管理页面设计成营销首页、定价页或数据大屏。
- 禁止为了视觉留白牺牲表格、筛选和批量操作效率。
- 禁止用大量彩色卡片替代结构化表格或状态流。
- 禁止页面内散落重复的颜色、字号和圆角常量。
- 禁止以整页刷新掩盖局部加载、错误或缓存问题。
- 禁止忽略空数据、失败、无权限和部分成功状态。
- 禁止危险操作无确认、无结果反馈或无审计入口。
- 禁止为单页装饰引入新的全局设计体系或大型 UI 依赖。

## 12. 界面验收清单

交付页面或交互前至少检查：

- 主要任务能否在清晰、短路径内完成
- 查询、重置、分页、排序和批量操作是否一致
- 加载、空数据、失败、无权限和部分成功是否完整
- 危险操作是否明确提示影响并二次确认
- 成功或失败后列表、统计和详情是否同步更新
- 中文文案、状态名称、日期、数字和单位是否准确
- 1280px 桌面和窄屏下是否仍可完成必要操作
- 是否复用了 Ant Design 和项目主题，而非复制样式常量
