# Dazah 工厂管理后台设计规范

## 1. 产品定位

Dazah 是原料药工厂的综合管理后台，不是营销网站或展示型应用。界面设计按以下顺序取舍：

1. 业务信息准确
2. 操作路径清晰
3. 权限和风险可识别
4. 状态与结果可追踪
5. 信息密度和操作效率
6. 视觉一致性

禁止使用大面积营销 Hero、定价卡、客户 Logo 墙、装饰性插画带或夸张标题来替代实际业务内容。

## 2. 设计事实来源

- 基础组件使用 Ant Design，优先使用组件原生能力。
- 颜色、字号、圆角和组件 token 以 `src/lib/antd-theme.ts` 为唯一事实来源。
- 全局样式以 `src/app/globals.css` 为准。
- 已有模块页面是交互参考，但明显违反本规范的旧页面不得作为新实现模板。

不要在页面中复制整套主题常量。确需新增全局 token 时，先确认多个模块的复用需求，再最小修改主题配置。

## 3. 页面结构

典型管理页按以下顺序组织：

1. 页面标题与必要说明
2. 关键状态、统计或风险提示
3. 查询和筛选区
4. 主操作与批量操作区
5. 表格、列表或业务工作区
6. 分页、结果摘要或操作记录

页面标题使用业务名称，不添加英文营销副标题。统计卡只展示能帮助判断和操作的指标，不为填充版面堆叠数字。

复杂业务按任务流分区，不按视觉装饰分区。常见信息应直接可见，低频高级选项可以折叠。

### 页面视觉基准

新建或改造页面以柔和、精致、有层次的企业后台界面为基准，同时保留清晰的业务信息和操作效率：

- 使用浅色中性背景承托白色内容卡片。页面背景、主工作区、卡片内分区形成有限的 Surface 层级；优先通过背景差异、间距和对齐建立结构，再使用弱边框、弱阴影辅助区分，避免以粗线条或层层描边分割内容。
- 主色采用低饱和紫色点缀，用于当前选中、主要操作、键盘焦点和少量关键标识。大面积背景保持中性，风险与业务状态继续使用语义色，不用紫色代替状态含义。
- 卡片、导航和控件使用与主题一致的柔和圆角；阴影保持轻微，边框只在相邻 Surface 需要界定时出现。同一页面控制层级数量，避免卡片内反复套卡片或堆叠装饰。
- 页面标题、导航、筛选和工作区之间保留舒展的留白，让不同任务易于扫描；表格、表单和操作区保持有效信息密度，不为追求“大留白”压缩数据或制造空白区域。
- 页面内部确有两级并列导航时，一级使用轻量胶囊分段导航，二级使用内容区左侧的垂直子导航；选中项通过背景、文字和细小标记共同识别。只有一个内容页时直接展示内容，不强行添加分段导航或空侧栏。
- 窄屏下分段导航允许横向滚动，二级子导航可转为横向入口；切换、键盘焦点和当前项必须清晰可辨。图标与文字配对，不能只靠图标或颜色表达入口含义。

颜色、圆角、阴影与组件状态从现有主题和全局样式取值，不在各页面复制一套视觉常量。

## 4. 布局与密度

- 顶部模块导航使用稳定尺寸的入口，当前模块以背景和底部标记识别；悬停、按下和页面切换等待时给出及时反馈，窄屏允许横向滚动。
- 侧边栏多级导航采用右侧浮层，保持侧边栏入口位置稳定；父级支持悬停和点击展开，浮层内可继续逐级向右浏览。主菜单与浮层的行高、间距和悬停反馈保持一致，选中态比悬停态更明确。浮层应有清晰边界，内容过长时内部滚动，不遮挡到无法访问的区域。
- 页面切换中的轻量状态提示使用不改变导航布局的浮动位置，避免侧栏菜单因提示出现而位移。
- 页面内的分段导航和垂直子导航服务于当前工作区，与全局模块导航及侧边栏浮层区分；同一层级入口保持稳定位置、尺寸和明确的选中反馈。

导航入口按目标页面区分直接导航、仅展开子菜单、同时支持导航和展开三种语义。
可导航父级的页面入口与展开入口分别可见、可点击、可用键盘操作；不能仅凭
`path` 非空推断父级标签可导航。悬停可展开，点击展开区域可切换，鼠标应能
连续移入浮层；离开后可收起，Escape 可关闭。路由变化不自动弹出浮层；选择
叶子入口后关闭浮层并导航。无悬停设备也必须能点击操作。

多级浮层向右展开时处理视口边缘和纵向溢出。同一层级的行高、对齐与间距一致，
悬停、选中、禁用及键盘焦点状态可区分。页面类型标识只描述入口直接到达的页面，
不因子级有仪表盘而标记父级；叶子不显示展开提示。模块首页与侧边栏使用相同
名称、目标路径和页面类型标识，快捷操作可以独立呈现。菜单页面的面包屑不重复，
随后展示中文标题、必要说明、关键状态和业务内容。导航等待反馈在路由完成或
超时后消失，并保留可访问的状态提示。
- 桌面端是主要工作环境，优先保证 1280px 及以上宽度的操作效率。
- 页面使用稳定的内容间距，避免大面积无业务意义留白。
- 筛选项较多时使用紧凑网格或可折叠高级筛选，不纵向堆成长表单。
- 操作按钮靠近其影响的数据区域；全局操作、批量操作和行操作必须分组明确。
- 同一页面避免同时出现多个视觉权重相同的主按钮。
- 长内容使用分区、抽屉、标签页或独立详情页，不能仅靠无限加高弹窗承载。

## 5. 表格与列表

表格是台账类页面的默认表达方式，应满足：

- 列名使用清晰中文，单位放在列名或值旁。
- 关键标识、状态和待办信息优先展示；低频字段可隐藏或放入详情。
- 内容可能过长时配置省略、换行、Tooltip 或可展开内容，禁止破坏列宽。
- 数据量较大时使用服务端分页、排序和筛选，不在浏览器一次加载全部记录。
- 宽表应设置横向滚动，并按需要固定标识列和操作列。
- 批量操作只有在选中数据后才可执行，并显示选择数量和适用范围。
- 行操作较多时保留一到两个高频操作，其余收入“更多”。
- 空数据必须区分“当前筛选无结果”“尚未创建数据”和“无权限查看”。

删除、作废、提交、审批、驳回、批量变更等操作必须展示对象、数量和不可逆影响。

## 6. 表单与录入

- 标签使用业务语言，必填项、单位、格式和示例要明确。
- 优先使用适合数据类型的控件，不用普通文本框代替日期、枚举、人员或数值控件。
- 校验错误靠近字段展示；提交失败后保留用户已输入内容。
- 提交期间禁用重复提交，并提供明确进度或处理中状态。
- 长表单按业务阶段或数据主题分组；关键字段不得藏在默认折叠区域。
- 编辑已有数据时，区分不可修改字段、当前值和将要变更的值。
- 离开未保存表单或覆盖他人新版本时，应给出提醒。

弹窗适合短小、单目标操作；字段多、需要对照上下文或存在多阶段流程时使用抽屉或独立页面。

## 7. 状态与反馈

每个异步区域都必须考虑：

- 初次加载
- 局部刷新
- 空数据
- 请求失败
- 权限不足
- 部分成功
- 重试或恢复方式

成功反馈说明完成了什么；失败反馈说明失败对象、可采取的动作和数据是否已保存。不要只显示“操作失败”。

状态不能只依赖颜色表达，必须同时使用中文文本，必要时配合图标。刷新、同步、导入和生成类长任务应展示任务状态、开始时间、完成结果和失败原因。

### 统一提示框与提示条

所有新建或修改的提示采用“分配角色”参考图的表达方式，并适配现有 Ant Design
主题：浅色圆角背景、左侧实心语义图标、中间简明正文、右侧“了解访问规则”入口。
页面说明、权限规则、风险提醒、错误与结果说明统一复用
`src/components/shared/PlatformNotice.tsx`（内部使用 Ant Design `Alert`）；
全局外观由 `src/lib/antd-theme.ts` 的 `Alert` token 控制，不在页面复制颜色和圆角。

- 使用无可见描边的浅色提示条，圆角及内间距遵循主题。正文简明且不另设第二行描述；
  完整规则、错误详情和补充说明通过 `description` 传入公共组件，在“了解访问规则”
  弹窗中阅读。重要风险与实际影响必须在简明正文中说明，不能仅藏于详情。
- 每条提示都提供“了解访问规则”入口，复用实际说明内容。可通过 `onLearnRules`
  复用已有只读规则弹窗；不得把写入操作绑定到规则入口。重试、刷新等原有操作通过
  `action` 保留在提示右侧，不因统一样式移除或改变行为。
- 信息使用浅蓝语义背景与信息图标；成功、警告、错误沿用各自浅色背景、语义图标和中文文案。
  不为贴近参考图而把风险或错误统一改成蓝色。主操作、选中态继续使用项目紫色主色。
- 入口必须可点击、可用键盘操作，并打开实际规则或执行明确动作。窄屏下文案自然换行，
  操作入口可移到下一行，不能遮挡正文或挤出横向滚动。
- 提示或确认弹窗使用 `Modal`：白色圆角容器、左侧业务标题及必要副说明、右上角关闭入口、
  分区清晰的正文、底部右对齐操作；正文过长时内部滚动，底部按钮始终可访问。
  主按钮只保留一个；“预览”应只展示当前配置，写入须通过明确的保存与必要确认。
- 字段校验仍靠近字段展示；短暂成功反馈继续使用 `message`，悬浮补充说明继续使用 `Tooltip`。
  它们按各自控件承担反馈任务，长规则或风险说明统一使用上述提示条或弹窗。

验收时检查提示的语义、图标、文本对比度、真实操作入口、键盘焦点和窄屏换行。
权限或风险提示必须准确说明实际生效范围，不因简化文案改变业务规则。

## 8. 风险、权限与审计

- 无权限时隐藏不应暴露的入口，或禁用入口并说明所需权限；不得让用户操作后才得到模糊错误。
- 高风险操作使用二次确认，确认文案包含动作、对象和影响。
- 审批、驳回、批准等人工责任判断必须让责任人明确作出，不得伪装成普通自动操作。
- 页面涉及关键状态流转时，应展示当前状态、允许的下一步和历史记录入口。
- 审计和日志页面优先展示操作人、时间、对象、动作、结果和失败原因。
- 敏感字段默认脱敏，不在通知、错误详情或前端日志中展示 secret、token、password、key。

## 9. 颜色、文字与图标

- 主色只用于主要操作、当前选中和必要强调，不用于大面积装饰背景。
- 成功、警告、错误、处理中、停用等状态使用稳定的语义映射。
- 同一业务状态在表格、详情、统计和筛选中保持相同文案与语义色。
- 正文和表格文字保持足够对比度；辅助文字不能淡到难以辨认。
- 页面标题、分区标题和正文形成有限层级，不使用 48px、80px 等营销展示字号。
- 图标用于帮助识别操作或状态，不能代替文字标签；同一图标不得表达多个相反动作。

## 10. 响应式与可访问性

- 桌面端保留完整查询、表格和批量操作能力。
- 窄屏优先保留搜索、关键筛选、关键字段、详情查看和必要轻量操作。
- 宽表在窄屏允许横向滚动或转为摘要列表，不强行压缩到不可读。
- 可点击目标应有足够尺寸，键盘焦点清晰，表单标签与控件正确关联。
- 不使用仅在 hover 时才可发现的关键操作或说明。
- 图表必须有标题、单位、图例和可读取的数值替代信息。

## 11. 禁止事项

- 禁止将管理页面设计成营销首页、定价页或数据大屏。
- 禁止为了视觉留白牺牲表格、筛选和批量操作效率。
- 禁止用大量彩色卡片替代结构化表格或状态流。
- 禁止页面内散落重复的颜色、字号和圆角常量。
- 禁止以整页刷新掩盖局部加载、错误或缓存问题。
- 禁止忽略空数据、失败、无权限和部分成功状态。
- 禁止危险操作无确认、无结果反馈或无审计入口。
- 禁止为单页装饰引入新的全局设计体系或大型 UI 依赖。

## 12. 界面验收清单

交付页面或交互前至少检查：

- 主要任务能否在清晰、短路径内完成
- 查询、重置、分页、排序和批量操作是否一致
- 加载、空数据、失败、无权限和部分成功是否完整
- 危险操作是否明确提示影响并二次确认
- 成功或失败后列表、统计和详情是否同步更新
- 中文文案、状态名称、日期、数字和单位是否准确
- 1280px 桌面和窄屏下是否仍可完成必要操作
- 是否复用了 Ant Design 和项目主题，而非复制样式常量
